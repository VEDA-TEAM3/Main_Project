# Risk 성능 지표 (Before / After)

| 항목 | 값 |
| --- | --- |
| 대상 | `ThresholdRiskPolicy` (`IRiskPolicy` 구현) |
| 측정 일자 | 2026-07-30 |
| 측정 방식 | **실측** — 전역 `operator new` 계측 + `steady_clock` p50 샘플링 |
| 측정 환경 | x86_64 / WSL2 / g++ `-O2` / 단일 스레드 |
| Before | 리팩터 이전 로직을 동일 파일에 재현 |
| After | 프로덕션 `ThresholdRiskPolicy.cpp` 를 그대로 링크 |

> **측정 환경 주의**: 라즈베리파이 4(ARM64)가 아니라 x86 개발 장비 수치다.
> 절대값은 Pi에서 3~5배 커진다. Pi 실측치는 `performance/control-server.md` 에 별도 갱신 필요.

## 측정 조건

| 파라미터 | 값 | 근거 |
| --- | --- | --- |
| 채널 수 | 12 | Pi 1대 최대 (CCTV 3대 × 4채널) |
| 차량 비율 | 50% | V×N 에서 V를 최대화하는 현실적 상한 |

| warmup | 200회 (측정 제외) | 버퍼 capacity 안정화 |

## 1. 핵심 성과 — 할당 (우선순위 3)

| N | Before | After |
| --- | --- | --- |
| 20 | 1.00회/프레임 | **0.00회/프레임** |
| 50 | 1.00회/프레임 | **0.00회/프레임** |
| 200 | 1.00회/프레임 | **0.00회/프레임** |

### Before의 1회

`domain::RiskEvaluation` 을 **값으로 반환**하면서 `zoneLevels` 벡터가 매 프레임 새로
할당됐다. 채널 12개 × `ZoneRisk`(약 24 B) ≈ 288 B, 초당 10회.

### After가 0인 이유

| 조치 | 효과 |
| --- | --- |
| `evaluate(frame, out)` out-parameter | 호출자(`Controller::riskEval_`)가 버퍼 재사용 → `resize` 가 no-op |
| `candPos_`/`candIdx_` 를 멤버로 | `clear()` 가 capacity 유지 → `reserve` 가 no-op |
| 로그 문자열을 rate-limit 통과 후 조립 | 억제된 호출에서 문자열 할당 없음 |

잔여 1회는 warmup 직후 첫 프레임의 잔여이며 이후 정상상태에서 0으로 유지된다.

## 2. 지연 (우선순위 2) — 중립, 노이즈 범위

**동일 바이너리를 5회 반복 측정한 결과다.** 단일 측정으로는 판단할 수 없을 만큼
WSL 환경의 분산이 컸다.

| N | Before (5회) | After (5회) |
| --- | --- | --- |
| 20 | 0.61 / 0.60 / 0.41 / 0.76 / 0.45 µs | 0.65 / 0.65 / 0.64 / 0.53 / 0.61 µs |
| 50 | 2.38 / 2.85 / 2.22 / 2.21 / 2.39 µs | 2.52 / 2.39 / 2.51 / 2.46 / 2.53 µs |
| 200 | 61.20 / 51.05 / 50.43 / 42.36 / 42.33 µs | 52.95 / 47.26 / 48.62 / 42.83 / 41.77 µs |

| N | Before 범위 | After 범위 | 판정 |
| --- | --- | --- | --- |
| 20 | 0.41 – 0.76 | 0.53 – 0.65 | 겹침 — 차이 없음 |
| 50 | 2.21 – 2.85 | 2.39 – 2.53 | 겹침 — 차이 없음 |
| 200 | 42.33 – 61.20 | 41.77 – 52.95 | 겹침 — 차이 없음 |

**결론: 지연은 개선되지 않았고 악화되지도 않았다.**

다만 After 쪽 분포가 세 경우 모두 **일관되게 더 좁다.** 프레임당 할당이 사라져 할당자
지터가 제거된 결과로 해석되며, 실시간 시스템에서는 중앙값보다 이 편이 유용하다.

> **과장하지 않는다.** 이 리팩터의 가치는 속도가 아니다. 안전 검사(비유한 좌표 필터)를
> O(N²) 이중 루프가 아니라 O(N) 사전 단계에 넣으면서 **비용을 늘리지 않은 것**이 성과다.

### 2.1 상충하는 두 변경

| 변경 | 방향 |
| --- | --- |
| 1단계 SoA 구축 (좌표 복사 O(N)) | 비용 **증가** |
| Rule 3의 gid 재탐색 O(N) 제거 | 비용 **감소** |
| 이중 루프가 80 B 객체 대신 16 B 좌표를 훑음 | 비용 **감소** |
| 유한성 검사 O(N) 추가 | 비용 **증가** |

넷이 상쇄되어 중립으로 나왔다.

### 2.2 기각한 대안 — 인덱스만 유지

`candPos_` 없이 `candIdx_` 만 두고 이중 루프에서 `frame.objects[candIdx_[m]].pos` 로
접근하는 변형을 측정했다.

| N | SoA (채택) | 인덱스만 (기각) |
| --- | --- | --- |
| 20 | 0.92x | **0.74x** |
| 50 | 0.89x | 0.99x |
| 200 | 1.01x | 1.04x |

*(Before 대비 배율. 1.0 초과가 개선)*

**작은 N에서 뚜렷하게 나빴다.** 간접 참조(인덱스 → 객체 → 좌표) 비용이 좌표 복사 비용보다
크다. 코드는 더 단순하지만 채택하지 않았다.

## 3. 프레임 예산 대비

윈도우 100 ms 기준. 위험 판정만의 비용이다.

| N | V (차량 50%) | 호출 수 | After (x86) | 예산 대비 | Pi 추정 (×4) | Pi 예산 대비 |
| --- | --- | --- | --- | --- | --- | --- |
| 20 | 10 | 190 | 0.6 µs | 0.0006% | 2.4 µs | 0.002% |
| 50 | 25 | 1,225 | 2.5 µs | 0.003% | 10 µs | 0.01% |
| 200 | 100 | 19,900 | 45 µs | 0.045% | 180 µs | 0.18% |
| 3,072 (이론상 최악) | 1,536 | 약 4.7 M | 약 10 ms | 10% | 약 40 ms | **40%** |

이론상 최악은 `channelCount(12) × kMaxObjectsPerFrame(256)` 이다. 집계기의 객체 수 상한이
이 표에 최악값이 존재하게 해 주는 근거다.

> 이 계층의 비용은 `IDistanceMetric` 호출 비용에 비례한다. 직전 `hypot`→`sqrt` 패치가
> 거리 계산을 5.17배 단축했으므로, 위 수치는 그 개선이 이미 반영된 값이다.
> 두 최적화는 곱해진다 — [Metric 성능 지표](./Metric_Performance_Metrics.md) 참고.

## 4. 안정성 검증

성능 측정과 같은 하네스에서 실행된다.

```
[OK]   metric=null 거부
[OK]   channelCount=0 거부
[OK]   channelCount=-1 거부
[OK]   warningDistance=NaN 거부
[OK]   dangerous>warning(역전) 거부
[OK]   NaN 객체 섞여도 차량 Danger 판정 유지 (level=Danger, nearest=2)
[OK]   최근접 객체 gid==0 이어도 Danger 판정 (level=Danger)
       (Before 동일 입력: level=None  <- 센티널 충돌로 경보 소실)
```

마지막 두 줄이 이 리팩터의 실질적 성과다. **정상 도메인 값(`gid = 0`)만으로 경보가
사라지던 경로가 재현되고 해소됐다.** 상세는
[Risk 보안 감사](./security/risk_security.md) 3.1 참고.

## 6. 회귀 감시

이 계층에는 런타임 성능 지표가 없다. 회귀는 코드 리뷰와 벤치마크로만 잡힌다.

| 회귀 | 증상 | 탐지 |
| --- | --- | --- |
| `evaluate` 를 값 반환으로 되돌림 | 프레임당 할당 1회 부활 | 없음 — **리뷰에서만** |
| `candPos_`/`candIdx_` 를 지역 변수로 | 프레임당 할당 2회 추가 | 없음 |
| 유한성 검사 제거 | NaN 경보 소실 재발 | 없음 — **무증상** |
| 인덱스 센티널을 gid로 되돌림 | `gid==0` 경보 소실 재발 | 없음 — **무증상** |

> **⚠️ 이 계층의 회귀는 전부 무증상이다.** 성능 회귀는 프레임 예산에 묻히고, 안전 회귀는
> "경보가 안 울린다"로만 나타나 로그조차 남지 않는다. `tests/` 등록이 유일한 자동 방어이며,
> control-server가 테스트 범위에 들어올 때 최우선으로 이관해야 한다.
