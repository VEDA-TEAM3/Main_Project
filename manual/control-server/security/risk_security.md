## 1. 위협 모델 (Threat Model)

Risk는 **판정이 하드웨어로 직결되는 유일한 계층**이다. `zoneLevels` 가 그대로 STM32로 나가
사이렌·부저·LED를 켠다. 다른 계층의 결함은 "값이 틀린다"로 끝나지만, 여기서는
**"경보가 울리지 않는다"** 로 끝난다.

| 출처 | 통제 주체 | 위협 |
|------|-----------|------|
| **`frame.objects[].pos`** | 상류 변환·융합 (간접적으로 원격 카메라) | NaN/Inf → 판정 무력화 |
| **`frame.objects[].gid`** | 융합 계층 | `gid == 0` → 센티널 충돌로 경보 소실 |
| **`frame.objects[].zoneId`** | `IZoneMapper` | 범위 밖 → 배열 OOB |
| **`warningDistance` / `dangerousDistance`** | 운영자 `config.json` / DI | NaN·음수·역전 → 판정 불능 |
| **`channelCount`** | 운영자 `config.json` / DI | 음수 → `size_t` 캐스팅 폭주 |

| 위협 범주 | 시나리오 | 성립 여부 |
|-----------|----------|-----------|
| **NaN/Inf 전파** | 비유한 좌표로 경보 무력화 | ✅ 차단 (1단계 사전 필터) |
| **센티널 충돌** | `gid == 0` 객체가 최근접일 때 경보 소실 | ✅ 차단 (인덱스로 대체) |
| **비유한/역전 임계값** | 설정만으로 경보 전체 무력화 | ✅ 조립 시점 throw |
| **0 나눗셈 / 발산** | 분모를 0으로 유도 | ✅ **구조적 불가 — 나눗셈이 없음** |
| **배열 OOB** | 범위 밖 `zoneId` 로 `zoneLevels` 밖 쓰기 | ✅ 인덱싱 전 검사 |
| **OOM (거대 할당)** | 음수 `channelCount` | ✅ 조립 시점 throw |
| **OOM (단편화)** | 프레임당 반복 할당 | ✅ **핫패스 할당 0** |
| **스택 오버플로** | 재귀·대형 지역 배열 | ✅ 구조적 불가 |
| **CPU 고갈** | 대량 객체로 V×N 증폭 | ℹ️ 상한 존재, 계산 가능 |
| **데이터 경합** | 다중 스레드 진입 | ⚠️ 스레드 안전 아님 (계약 의존) |

### 실패 방향 분석

| 방향 | 결과 | 평가 |
|------|------|------|
| **과소 판정** (위험을 놓침) | 사이렌이 울리지 않음 | ⚠️ **인명 위험 — 최악** |
| **과대 판정** (없는 위험을 알림) | 불필요한 경보 | 오경보 (경미) |

> **⚠️ 이 계층의 모든 부동소수 결함은 과소 판정 방향으로 실패한다.** NaN은 모든 비교에서
> false이므로 "위험 없음"으로 귀결된다. 이것이 본 감사가 NaN을 최우선으로 다루는 이유다.

## 2. 부동소수 안전성 (Floating-Point Safety)

### 2.1 ✅ NaN/Inf 좌표 — 1단계 사전 필터로 차단

**리팩터 전에는 방어가 전혀 없었다.**

```cpp
double dist = metric_->calculate(vehicle.pos, other.pos);   // NaN in -> NaN out
if (dist < minDist) { ... }                                  // NaN < x 는 항상 false
```

> **⚠️ 초판 정정 (변이 검증으로 확인)**: 초판은 "NaN 객체가 섞이면 차량이 판정에서 통째로
> 빠져 경보가 사라진다"고 기술했다. **이는 사실이 아니다.** 유한성 필터를 제거한 변이
> 빌드로 `RiskTest` 전체를 돌린 결과 **모든 테스트가 통과했다.**
>
> 이유는 NaN 비교 의미 자체에 있다. `minDist` 는 `max()` 로 시작하고 `dist < minDist` 는
> NaN 에 대해 false 이므로, 필터가 없어도 **NaN 객체는 애초에 최근접으로 뽑히지 않는다.**
> 차량은 유한 좌표 객체들 중에서 정상적으로 최근접을 찾는다.
>
> 즉 이 계층에서 NaN 의 실패 방향은 **이미 안전 쪽(무시)** 이다.

| 판정식 | NaN일 때 | 실제 결과 |
|--------|----------|-----------|
| `dist < minDist` | false | NaN 객체가 최근접 후보에서 자연히 배제됨 (안전) |
| 차량 자신이 NaN | 모든 비교 false | 그 차량만 판정 제외 — 위치를 모르므로 **올바른 동작** |
| `minDist <= dangerousDistance_` | 도달 안 함 | `minDist` 에 NaN 이 들어갈 경로가 없음 |

**그렇다면 필터의 가치는 무엇인가**: 다층 방어(defense-in-depth)와 관측성이다.

- 배제가 **명시적**이 되고 `nonFiniteCount_` 로 **로그에 남는다.** 필터가 없으면 비유한
  좌표가 유입되고 있다는 사실 자체를 아무도 모른다.
- 이중 루프가 **유한 값만 본다는 것이 보장**된다. 나중에 `<` 를 `<=` 로 바꾸거나
  제곱거리 경로를 추가하면 NaN 의 안전성이 조용히 뒤집힐 수 있는데, 그때 이 필터가
  전제를 지켜 준다.
- `IDistanceMetric` 은 DI 로 교체된다. 다른 구현이 비유한 입력에 대해 **유한한 쓰레기 값**을
  돌려주면 NaN 의 "비교 false" 안전성이 성립하지 않는다.

> **NaN 이 실제로 해로운 곳은 융합 계층이다.** `ConcatFuser`/`GridFuser`의
> `if (dist > dedupMergeDistance_) continue;` 는 NaN 에 대해 false 라 **continue 하지 않고
> 병합으로 진행**한다. 서로 다른 실체가 하나로 뭉개진다. 그쪽은 별도 감사·테스트가 필요하며
> 본 문서 범위 밖이다.

**조치**: 이미 존재하던 O(N) 초기화 루프에 유한성 검사를 얹고, 통과한 객체만
`candIdx_`/`candPos_` 에 적재한다. 이중 루프는 유한한 좌표만 본다.

```cpp
if (!isFinitePoint(obj.pos)) { ++droppedThisFrame; continue; }
candPos_.push_back(obj.pos);
candIdx_.push_back(static_cast<std::uint32_t>(i));
```

> **왜 O(N) 단계인가**: 이중 루프 안에서 검사하면 같은 방어가 O(N²)가 된다.
> 상류 `AffineLocalToWorldTransform` 도 NaN을 통과시킨다(범위 검사가 `<`/`>` 기반이라
> NaN에 대해 전부 false) — 이 계층이 마지막 방어선이다.

**실측 검증**: NaN 객체가 섞인 프레임에서 나머지 차량의 `Danger` 판정이 유지됨을 확인했다.

### 2.2 ✅ 비유한·음수·역전 임계값 — 조립 시점 차단

```cpp
if (!std::isfinite(warningDistance_) || !std::isfinite(dangerousDistance_) ||
    warningDistance_ < 0.0 || dangerousDistance_ < 0.0) { throw ...; }
if (dangerousDistance_ > warningDistance_) { throw ...; }
```

| 잘못된 값 | 리팩터 전 결과 |
|-----------|----------------|
| `warningDistance = NaN` | `minDist <= NaN` 항상 false → **경보 완전 사망** |
| `dangerousDistance = -1` | 영원히 성립 안 함 → Danger 소실 |
| `dangerous(10) > warning(5)` | `<= 10` 이 먼저 걸려 **Warning 도달 불가** |

`AppConfig` 는 `dedupMergeDistance >= warningDistance` 만 경고하며, **이 세 가지는
검증하지 않는다.** 생성자가 마지막 방어선이다.

역전을 warning이 아니라 throw로 막는 이유: 과다 경보라 안전 방향이긴 하나, 운영자가
설정한 2단계 판정이 **조용히 1단계가 되는** 것은 설정 의도의 무시다.

### 2.3 ✅ 0 나눗셈 / 발산 — 구조적으로 성립 불가

이 계층에는 나눗셈이 없다. 거리 계산은 `IDistanceMetric` 에 위임되며, 그쪽도
`sqrt(dx*dx + dy*dy)` 로 나눗셈이 없다
([Metric 보안 감사](./metric_security.md) 2.1).

### 2.4 ✅ 경계 조건 — 임계값과 정확히 같을 때

```cpp
if (minDist <= dangerousDistance_)      // 포함
else if (minDist <= warningDistance_)   // 포함
```

`<=` 이므로 **정확히 임계값인 경우 더 위험한 쪽으로 분류된다.** 안전 방향이며 의도적이다.
`dangerousDistance == warningDistance` 인 설정도 허용되며(역전이 아님), 이 경우 Warning은
도달 불가능하지만 그것은 운영자가 명시적으로 선택한 1단계 판정이다.

## 3. 논리 안정성 (Logical Stability)

### 3.1 ✅ `gid == 0` 센티널 충돌 — 인덱스로 대체

**리팩터 전 코드:**

```cpp
veda::GlobalId nearestGid = 0;      // "못 찾음" 센티널
...
if (nearestGid == 0) continue;      // 판정 포기
```

그런데 **`gid == 0` 인 객체는 실제로 존재한다.** `ConcatFuser.cpp:162` 가 `wObj.gid = 0` 을
초기값으로 넣으며, 어떤 경로로든 gid 배정을 받지 못한 객체는 0을 달고 나온다.

그런 객체가 차량의 최근접 대상이면 `nearestGid` 가 0으로 남아 **못 찾은 것으로 오인되고,
그 차량은 판정에서 제외되어 경보가 사라진다.**

**실측 검증** (차량 1대 + 1 m 거리의 `gid==0` 보행자):

```text
[OK]   최근접 객체 gid==0 이어도 Danger 판정 (level=Danger)
       (Before 동일 입력: level=None  <- 센티널 충돌로 경보 소실)
```

**조치**: `kNoIndex = 0xFFFFFFFF` 인덱스 센티널로 대체. 인덱스는 `frame.objects` 의 위치이므로
값 충돌이 원리적으로 불가능하다.

> **⚠️ 이것은 이론적 결함이 아니다.** 위 재현은 정상적인 도메인 값(`gid = 0`)만으로
> 경보가 사라지는 것을 보인다.

### 3.2 ✅ `zoneId` 범위 검사 — 인덱싱 전에 수행

```cpp
if (vehicle.zoneId < 0 || vehicle.zoneId >= channelCount_) { logError(...); continue; }
auto& zone = out.zoneLevels[static_cast<std::size_t>(vehicle.zoneId)];
```

리팩터 전에도 있었고 유지했다. 하한(`< 0`)을 함께 보는 것이 중요하다 — `ChannelId` 는
부호 있는 타입이고, 미배정 객체는 `zoneId == -1` 을 갖는다(`SpatialZoneMapper` 가 어떤
AABB에도 속하지 않는 객체에 부여). `size_t` 캐스팅되면 거대한 인덱스가 된다.

### 3.3 ✅ `channelCount` 범위 — 거대 할당 차단

```cpp
out.zoneLevels.resize(static_cast<std::size_t>(channelCount_));   // channelCount = -1 이면?
```

`-1` → `size_t` 캐스팅 시 `18446744073709551615`. 생성자에서 `[1, 256]` 을 강제한다.

### 3.4 ⚠️ 스레드 안전 — 계약 의존

`riskLogCount_` 와 `nonFiniteCount_` 가 가변 멤버이고, `candPos_`/`candIdx_` 는 공유
스크래치 버퍼다. **동시 진입하면 데이터 경합이다.**

`Controller::processPipeline` 이 단일 스레드로 돈다는 가정에 의존하며, 그 가정은
Receiver 구현에 달려 있다(실배포는 단일 `PipelineWorker`).
[Aggregator 보안 감사](./aggregator_security.md) A2와 같은 뿌리다.

## 4. 메모리 & 성능

### 4.1 ✅ 프레임당 힙 할당 0

| 발생원 | 리팩터 전 | 현재 |
|--------|-----------|------|
| `RiskEvaluation::zoneLevels` (값 반환) | 1회/프레임 | 0 (out-parameter 재사용) |
| 스크래치 버퍼 | 없음 | 0 (멤버 + `clear()`) |

**실측: 프레임당 1.00회 → 0.00회**

`out.zoneLevels.resize(channelCount_)` 는 정상 운용에서 매 프레임 같은 값이므로 no-op이다.
`candPos_`/`candIdx_` 는 `clear()` 후 `reserve()` — `clear()` 가 capacity를 유지하므로
warmup 이후 `reserve` 도 no-op이다.

### 4.2 ✅ 스택 오버플로 — 구조적 면역

- **재귀 없음** — `evaluate()` 는 3개의 평면 루프다.
- 지역 저장소는 `double`/인덱스 몇 개 — 입력 크기와 무관한 **O(1)**.
- VLA·`alloca`·대형 `std::array` 없음. 스크래치는 전부 힙 기반 멤버 벡터다.

### 4.3 ℹ️ V×N 증폭 — 상한 계산 가능

| N (객체) | V (차량, 50%) | 호출 수 | 실측 (x86) | 프레임 예산(100ms) |
|----------|---------------|---------|------------|--------------------|
| 20 | 10 | 190 | 약 0.5 µs | 0.0005% |
| 50 | 25 | 1,225 | 약 2.5 µs | 0.003% |
| 200 | 100 | 19,900 | 약 45 µs | 0.045% |
| 3,072 (이론상 최악) | 1,536 | 약 4.7 M | 약 10 ms | 10% |

이론상 최악은 `channelCount(12) × kMaxObjectsPerFrame(256)` 이다. 집계기의 객체 수 상한이
이 표에 최악값이 존재하게 해 주는 근거다.

### 4.4 ℹ️ 지연은 중립 (측정 노이즈 범위)

리팩터 전후 `evaluate()` p50을 5회 반복 측정한 결과, 두 분포가 겹친다.

| N | Before 범위 | After 범위 |
|---|-------------|------------|
| 20 | 0.41 – 0.76 µs | 0.53 – 0.65 µs |
| 50 | 2.21 – 2.85 µs | 2.39 – 2.53 µs |
| 200 | 42.33 – 61.20 µs | 41.77 – 52.95 µs |

**중앙값 기준 유의미한 차이가 없다.** 다만 After 쪽 분포가 일관되게 **더 좁다** —
프레임당 할당이 사라져 할당자 지터가 제거된 결과로 보인다.

> **본 리팩터의 가치는 지연 단축이 아니라 정확성과 무할당이다.** SoA·인덱스화·분기 제거는
> 안전 검사(2.1)를 O(N²)가 아닌 O(N)에 넣기 위한 구조 변경이었고, 그 대가로 지연이
> 늘지 않았다는 것이 측정 결과다. 과장하지 않는다.

### 범위 밖 — 상류 권고

| # | 항목 | 등급 | 내용 |
|---|------|------|------|
| **U1** | `AffineLocalToWorldTransform` 이 비유한 좌표를 통과시킴 | ℹ️ Info | `worldX < minX \|\| worldX > maxX` 형태라 NaN에 대해 전부 false → 폐기되지 않는다. 본 리팩터의 2.1이 하류에서 막았으므로 **경보 소실은 해소**되었으나, 근본적으로는 좌표가 생성되는 지점에서 거르는 편이 낫다. (융합 계층도 같은 NaN을 보게 되므로) |

**총평**: 리팩터 전 Risk 계층에는 **경보를 조용히 소실시키는 경로가 둘** 있었다. —
`gid==0` 센티널 충돌과 비유한·역전 임계값 <br> 둘 다 컴파일 오류도 런타임 오류도
로그도 남기지 않고 **"위험 없음"** 으로 귀결되며, 이는 충돌 경보 시스템에서 가능한 최악의
실패 방향이다. 특히 `gid==0` 은 이론적 시나리오가 아니라 정상 도메인 값으로 재현되었고,
**변이 검증에서도 3개 테스트가 실패해 회귀 가드가 실제로 작동함을 확인했다.**

> **초판 정정**: 초판은 여기에 비유한 좌표를 세 번째 경로로 넣었으나, 변이 검증 결과
> **NaN 은 원래부터 안전 방향으로 실패**하고 있었다. 해당 필터는 결함 수정이 아니라
> 다층 방어·관측성 강화다.

두 경로 모두 차단했고 실측으로 확인했다. 메모리는 프레임당 할당 1회에서 0회가 되었다.
**지연은 개선되지 않았다** — 측정 노이즈 범위 안이며, 그렇게 보고한다(4.4). 이 리팩터의
가치는 속도가 아니라 안전 검사를 O(N²)가 아닌 O(N)에 넣으면서 비용을 늘리지 않은 데 있다.

남은 위험은 **A1(궤적 미고려)** 이며, 이는 결함이 아니라 현재 사양의 경계다. 거리만으로
판정하는 한 "접근 중"과 "멀어지는 중"을 구분할 수 없다는 점은 운영자가 알고 있어야 한다.
