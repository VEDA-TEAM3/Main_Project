# Control-server `fuse` 최적화 보고서

> 후속 변경: 2026-07-29에 `GridFuser` 출력 좌표에 선택적 공간 히스테리시스가 추가됐다.
> 이 문서의 `ConcatFuser` 동일성 및 성능 수치는 `positionJitterRadius=0` 조건이다.
> 실제 `AppContext` 기본값은 현재 `0.15m`이며, 좌표 안정성과 추가 처리비용은
> `world-position-stabilization-2026-07-29.md`에 별도로 기록했다.

- 작성일: 2026-07-29
- 대상: `control-server/src/fuse`
- 기준 구현: `ConcatFuser`
- 적용 구현: 적응형 `GridFuser`

## 1. 결론

실제 애플리케이션 조립 코드가 `ConcatFuser` 대신 `GridFuser`를 사용하도록 변경됐다.
정상 입력이 96개 미만이면 기존과 같은 전체 쌍 비교를 실행하고, 96개 이상이면 공간 해시
그리드로 가까울 가능성이 있는 쌍만 비교한다. 비유한 좌표, 32비트 셀 범위를 넘는 좌표,
`NaN` 병합 임계값도 기존 전체 비교 경로로 되돌린다.

아래 표는 동일한 4채널 중첩 관측 입력을 사용한 3회 독립 실행 결과의 중앙값이다.
각 독립 실행 내부에서도 9개 측정값의 중앙값을 사용했다.

| 전체 관측 객체 | 실제 객체 | 최적화 전 `ConcatFuser` | 최적화 후 `GridFuser` | 배속 | 지연 감소 |
|---:|---:|---:|---:|---:|---:|
| 64 | 16 | 12.011 µs/frame | 11.807 µs/frame | 1.02× | 1.70% |
| 128 | 32 | 38.721 µs/frame | 23.588 µs/frame | 1.64× | 39.08% |
| 256 | 64 | 143.673 µs/frame | 46.717 µs/frame | 3.08× | 67.48% |
| 512 | 128 | 500.936 µs/frame | 108.138 µs/frame | 4.63× | 78.41% |
| 1,024 | 256 | 2,038.790 µs/frame | 198.310 µs/frame | 10.28× | 90.27% |

계산식:

```text
배속 = 최적화 전 시간 / 최적화 후 시간
지연 감소율(%) = (1 - 최적화 후 시간 / 최적화 전 시간) × 100
```

예를 들어 1,024개 입력의 계산은 다음과 같다.

```text
배속 = 2,038.790 / 198.310 = 10.28배
지연 감소율 = (1 - 198.310 / 2,038.790) × 100 = 90.27%
```

## 2. 변경 내용

### 운영 경로 변경

`control-server/src/core/AppContext.cpp`에서 실제 주입 구현을 다음과 같이 교체했다.

```cpp
// 변경 전
std::make_shared<ConcatFuser>(...)

// 변경 후
std::make_shared<GridFuser>(...)
```

`ConcatFuser`는 기준 구현과 회귀 비교 대상으로 그대로 보존한다.

### 적응형 비교 경로

`GridFuser`는 입력 수에 따라 다음 경로를 선택한다.

```text
후보 < 96
  → ConcatFuser와 같은 순서의 전체 쌍 비교 및 즉시 union

후보 ≥ 96, 좌표와 임계값을 안전하게 격자화 가능
  → 공간 해시의 3×3 인접 셀에서만 근접 후보 수집
  → (i,j) 사전순 정렬
  → 기존과 같은 순서로 union

비유한/극단 좌표 또는 NaN 임계값
  → 전체 쌍 비교 폴백
```

96이라는 전환점은 첫 측정에서 64개 입력은 그리드 준비 비용 때문에 느려지고 128개부터
빨라지는 것이 확인되어 그 사이 값으로 정했다. 따라서 작은 입력을 억지로 그리드에 넣지 않는다.

### 지연 할당

16,384개 공간 해시 버킷은 `GridFuser` 생성 시점에 만들지 않는다. 실제로 96개 이상의 정상
입력이 들어와 그리드 경로를 처음 실행할 때 한 번만 할당한다. 작은 프레임만 처리하는 실행에서는
이 메모리를 할당하지 않는다.

### 예외 입력 동작 보존

기존 `GridFuser`는 아래 입력에서 `floor(value / cellSize)`를 `int32_t`로 바꾸기 때문에
`ConcatFuser`와 동일하다고 보장할 수 없었다.

- `NaN`, `+Inf`, `-Inf` 좌표
- 셀 인덱스가 `int32_t` 범위를 넘는 큰 유한 좌표
- `NaN`인 `dedupMergeDistance`

현재 구현은 이런 입력을 감지해 전체 비교 경로로 폴백한다. 정상 운영 입력은 상류에서 비유한
좌표가 제거되지만, 회귀 안전성을 상류 구현에만 의존하지 않도록 만든 것이다.

## 3. 비교량 감소

기준 구현은 모든 무순서 쌍을 확인하므로 최대 비교 쌍 수가 다음과 같다.

```text
N × (N - 1) / 2
```

벤치마크 입력은 실제 객체 하나를 4개 채널이 각각 관측하도록 만들었다. 실제 객체별 채널 간
근접 쌍은 `4 × 3 / 2 = 6`개다.

| 전체 관측 `N` | 기준 최대 쌍 `N(N-1)/2` | 그리드 근접 쌍 `실제 객체×6` |
|---:|---:|---:|
| 64 | 2,016 | 작은 입력 폴백으로 2,016 |
| 128 | 8,128 | 192 |
| 256 | 32,640 | 384 |
| 512 | 130,816 | 768 |
| 1,024 | 523,776 | 1,536 |

그리드 경로도 해시 버킷 충돌로 먼 후보를 볼 수 있으며, 최종 병합 전에는 반드시 실제 거리
계산을 다시 한다. 위 근접 쌍 수는 충돌이 없는 이 벤치마크 입력 구조에서의 값이다.

검증 범위:

1. 동일 채널 객체를 병합하지 않는 규칙
2. 서로 다른 클래스를 병합하지 않는 규칙

4. 클러스터 내 동일 채널 중복 금지
5. 융합 좌표의 산술평균

7. `(channel, ObjectId)` 기반 `gid` 승계
8. 거리 기반 추적 fallback
9. 감지 누락 coasting과 5윈도우 이후 만료
10. 객체 순서와 원본 채널 순서
11. 비유한 좌표, 극단 좌표, `NaN` 임계값

비교 대상 필드:

- 프레임 타임스탬프와 위험도
- 객체 수와 순서
- `gid`, 클래스
- `x`, `y`의 IEEE-754 비트값
- 객체 위험도, 최근접 객체와 거리
- `zoneId`
- 원본 채널 수, 순서, 잘림 상태

테스트 실행 시간은 현재 머신에서 약 80 ms였다. `AppContext.cpp`도 변경 후 `-fsyntax-only`
컴파일을 통과했다.

- 옵션: `-std=c++20 -O2 -DNDEBUG -pthread`
- 운영체제: Windows NT 10.0.26200, x64
- 프로세서 식별자: Intel64 Family 6 Model 140 Stepping 1

## 6. 한계와 다음 검증

이번 결과는 현재 Windows/MinGW 머신의 합성 입력 결과다. Raspberry Pi 또는 실제 배포 Linux의
절대 지연시간이라고 주장할 수 없다. 특히 1,024개 입력의 최적화 시간은 독립 실행 사이에
179~408 µs로 변동했다. 표에는 계획대로 중앙값을 사용했지만, 실제 배포 판단에는 타깃 장비의
CPU 고정 주파수와 실제 MQTT 프레임 기록으로 재측정해야 한다.

또한 500개 생성 윈도우와 명시적 엣지 테스트 통과는 강한 회귀 증거지만 모든 가능한 입력에
대한 수학적 증명은 아니다. 현재 운영 조립처럼 `EuclideanMetric`을 사용하는 조건에서 공간
그리드의 근접성 보장이 성립한다. 향후 `IDistanceMetric`에 좌표 차이와 무관한 사용자 정의
거리 함수를 주입한다면 그 구현은 그리드 pruning 계약을 별도로 만족해야 한다.

현재 머신에는 저장소의 기존 Linux 전체 빌드 캐시가 요구하는 `/usr/bin/cmake`,
`/usr/bin/c++`, 시스템 `nlohmann_json`, `libmosquitto` 조합이 없다. 따라서 전체 서버 링크는
이번 측정에서 실행하지 못했다. 대신 변경된 fuser 프로덕션 소스 전체를 직접 컴파일·링크했고,
추가 GTest를 실행했으며, `AppContext.cpp`의 구문 컴파일까지 확인했다.
